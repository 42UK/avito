# Резервное копирование PostgreSQL (локальная среда)

Сценарии запускаются из любого каталога, используют root `compose.yaml` и
требуют работающий Compose service `postgres`. Скрипты не запускают backup
автоматически. Файлы создаются в игнорируемом `backups/`, с правами,
ограниченными `umask 077`; храните их в защищённом месте, не коммитьте и не
публикуйте. Backup может содержать все локальные данные приложения.

## Создать backup

```sh
./scripts/backup-postgres.sh
./scripts/backup-postgres.sh before-schema-change.dump
```

Формат — PostgreSQL custom archive (`pg_dump -Fc`), без owner/ACL. Существующий
файл не перезаписывается. При ошибке неполный файл удаляется. Скрипт не
сохраняет `.env` и не записывает пароль в аргументы/слои образа.

## Проверить восстановление

Восстановление всегда создаёт **новую отдельную базу**, по умолчанию
`avito_deals_restore_<pid>`; можно задать имя вручную:

```sh
./scripts/restore-postgres.sh backups/before-schema-change.dump
./scripts/restore-postgres.sh backups/before-schema-change.dump local_restore_check
```

Скрипт откажется использовать имя настроенной основной базы и не удаляет
существующие базы. Он не переключает backend на восстановленную базу: проверьте
результат отдельным подключением, затем удалите restore-базу только после
осознанного решения. При сбое импорта новая база может остаться частично
восстановленной; проверьте её вручную. Не указывайте здесь production
подключение. Для переносимости используйте совместимую версию PostgreSQL.
